# 打工模式键盘映射功能 — 开发计划

> 版本: v1.0 草案
> 目标: 打工模式下全局热键注册 + 小狗按键盘视觉反馈

---

## 1. 功能概述

在打工模式下，线条小狗趴在书桌上，面前放着一块小键盘。用户按下设定的热键时：

1. 小狗做出按键盘的动作（对应按键位置不同）
2. 按键对应的键盘按键高亮/发光
3. 执行映射的动作（发送文本、打开应用、模拟按键等）

---

## 2. 需求分解

### 2.1 核心功能

| # | 需求 | 优先级 |
|---|------|--------|
| 1 | 打工模式下注册全局热键，不聚焦也能响应 | P0 |
| 2 | 用户可配置热键→动作映射（配置文件） | P0 |
| 3 | 按键时切换小狗动画 + 键盘视觉反馈 | P0 |
| 4 | 按键动画结束后回到默认打工姿态 | P1 |
| 5 | 用户可通过右键菜单编辑映射 | P2 |
| 6 | 多热键组合（Ctrl/Alt/Shift + 字母键） | P1 |
| 7 | 防止按键映射影响正常打字 | P1 |

### 2.2 支持的映射动作

| 动作类型 | 示例 |
|----------|------|
| 模拟按键 | 按 Ctrl+C |
| 发送文本 | 自动输入一段文字 |
| 打开文件/程序 | 启动计算器 |
| 打开URL | 打开网页 |
| 系统操作 | 音量增减、静音 |
| 运行脚本 | 执行 bat/ps1 |

### 3.2 技术选型：全局热键

**方案 A：`ctypes` + Windows `RegisterHotKey`（推荐）**

```
优点: 零依赖，不要求管理员权限，精准
实现: 通过 WM_HOTKEY 消息接收按键事件
局限: 仅限 Windows；HotKey ID 有限（约 256）
```

**方案 B：`keyboard` 库**

```
优点: 跨平台，API友好
缺点: Windows 需要管理员权限；增加外部依赖
```

**结论：采用方案 A，ctypes 方案最轻量且符合项目现有"零额外依赖"的原则。**

### 3.3 配置格式

`config/hotkeys.json`：

```json
{
  "version": 1,
  "mappings": [
    {
      "id": "screenshot",
      "hotkey": "ctrl+shift+s",
      "action": "simulate_keys",
      "params": {"keys": "win+shift+s"},
      "description": "截图工具"
    },
    {
      "id": "calc",
      "hotkey": "ctrl+alt+c",
      "action": "open_file",
      "params": {"path": "calc.exe"},
      "description": "打开计算器"
    },
    {
      "id": "greeting",
      "hotkey": "ctrl+alt+g",
      "action": "type_text",
      "params": {"text": "好的，马上处理！"},
      "description": "快速回复"
    }
  ]
}
```

### 3.4 动画素材方案

由于现有 GIF 素材是"线条小狗"风格，**建议采用分层渲染**而非单独制作每个按键的 GIF：

#### 分层渲染架构

```
打工模式窗口 (透明)
  ├─ QLabel: 小狗本体动画 (现有 work GIF)
  └─ QLabel: 键盘叠加层 (pixel art / SVG)
       └─ 按键高亮: 按下的键发光闪烁
```

**键盘叠加层方案：**
- 用 PySide6 的 `QPainter` 直接绘制像素风键盘
- 或使用预制的透明 PNG 键盘底图 + 按键高亮 PNG
- 按下的键改变颜色/发光（通过 QLabel 切换或直接绘图）

**小狗动画方案：**

有三种实现方式可选，按复杂度递增排列：

| 方案 | 做法 | 素材需求 | 效果 |
|------|------|---------|------|
| A. 姿势切换 | 用不同的"按键盘"静态姿势 GIF 代替当前 work GIF | 每个热键对应一个"手在键盘上"的 GIF | 不同按键不同姿势 |
| B. 手部叠加 | work 动画基础上叠放手部移动动画 | 小狗身体底层 + 手部 PNG 序列 | 更动态 |
| C. 全动画 | 制作完整的"伸手→按键→收手"循环 GIF | 需要完整的多帧 GIF | 最自然 |

**推荐：方案 A（初期）→ 后期可升级到 B/C。**

## 5. 素材制作计划

### 5.1 需要准备什么

**如果你自己准备素材：**

| 素材 | 规格 | 数量 |
|------|------|------|
| 小狗按键盘 GIF | 透明底，与 work GIF 同尺寸，白底/线条风格，手在键盘上 | 每个热键区域 1 个（建议至少 3-4 个覆盖左右中） |
| 键盘底图 PNG | 透明底，像素风键盘布局 | 1 张 |
| 按键高亮 PNG | 单个键位高亮/发光效果 | 按按键数量 |

### 5.2 我能否生成素材

可以使用两种路线：

**路线①：pixel-art 风格（推荐）**
- 我可以调用 pixel-art skill，生成像素风格的键盘底图 + 按键高亮
- 气质和现有的"线条风格"小狗可能略有差异，但简洁可爱
- 如果你有原有的线条小狗素材源文件（分层 PSD/PNG），我可以协助合成

**路线②：GIF 动图辅助合成**
- 你提供小狗 work pose 的 PNG 帧
- 我用图像处理工具合成按键盘的变体帧
- 然后用 ffmpeg 组装成 GIF

**现状约束：** 
- 我没有现成的"线条小狗按键盘"素材库
- 生成完全匹配现有画风的 GIF 帧序列，需要至少 3-4 帧/姿势，总素材量约 12-16 帧
- **建议：我先用 pixel-art 做一批试制素材（2 个按键示范），你看效果再决定方向**

## 6. 风险与待定项

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| RegisterHotKey 被其他程序占用 | 热键失效 | 注册失败时 fallback 提示用户换键 |
| GIF 素材风格不统一 | 视觉割裂 | 先用 pixel-art 试制 2 个确认风格 |
| 键盘叠加层遮挡小狗 | 画面混乱 | 键盘放在窗口底部 30%，小狗在上部 70% |
| 管理员权限下全局热键 | 无问题 | RegisterHotKey 在普通用户也能工作 |
| 多个热键同时按下 | 动画冲突 | 设置按键动画互斥，和现有 `_interaction_in_progress` 统一管理 |
